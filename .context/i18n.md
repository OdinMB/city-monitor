## Plurals

A string with a number in it takes `count` (`t('time.minutesAgo', { count: 5 })`) and is stored as i18next plural keys: `key_one`, `key_other`, and in Arabic `key_zero`, `key_one`, `key_two`, `key_few`, `key_many`, `key_other`. i18next picks the form with `Intl.PluralRules`, per language, and falls back to the bare `key` when a language has no plural keys for it.

- **Arabic needs all six CLDR forms.** One and two are words without the numeral ("منذ دقيقة", "منذ دقيقتين"), 3–10 take the plural noun ("منذ 3 دقائق"), 11–99 the singular accusative ("منذ 11 دقيقة", "خلال 14 يومًا") and 100–102 the singular ("منذ 100 يوم"). Every Arabic string with `{{count}}` has the six forms unless its wording does not change with the number ("{{count}} أخرى"); `src/i18n/plurals.test.ts` fails otherwise, so a new count string goes there too.
- **English and German** add `_one`/`_other` only where the noun changes ("1 agenda item"); abbreviated units ("5 min ago", "vor 3 Std.") stay one bare key. **Turkish** keeps the singular after a number, so one bare key.
- Pass the number as `count`, not under another name, or no plural form is chosen. Don't build "N + translated noun" by concatenation; put the number in the string.

Pluralised now: `time.minutesAgo/hoursAgo/daysAgo`, `panel.appointments.inDays`, `panel.councilMeetings.agendaItems`, `panel.political.{representatives, districtMayors, seats}`, `mapPopup.delay`.

## Right-to-left (Arabic)

`App.tsx` sets `<html dir="rtl">` for Arabic, so the layout mirrors and the browser's bidi algorithm orders mixed text. Four things it gets wrong need code:

- **Phone numbers and numeric ranges** are reordered when they stand alone in right-to-left text ("030 390 63-90" as "63-90 390 030"). Wrap them in `<Ltr>` (`components/Ltr.tsx`, a `<bdi dir="ltr">`) in React, or `ltr()` (`map/popups.ts`) in popup HTML. Used for the crisis hotline numbers, the pharmacy phone and the roadworks validity range. A range inside a translated sentence ("إثنين–سبت 14–20", "اليوم 09:00 – غداً 09:00") keeps the sentence's right-to-left order and is left alone.
- **Arrows that mean "more / continue / until"** use `forwardArrow()` (`lib/bidi.ts`): "→", or "←" in Arabic. Arrows for a physical direction or a data trend ("A → B" between German place names, the wastewater trend arrows, expand/collapse chevrons, the "↗" external-link mark) keep their glyph.
- **Arrow keys in tab lists** (`useTabKeys`) follow the visual order: in Arabic ArrowLeft moves to the next tab.
- **Feed text** (news headlines and sources, police reports, NINA warnings, transit messages, event titles, council meetings, representatives' names) is German in an Arabic page, and bidi moves its neutral characters around ("[Synthetisch] Straßenfest …" ends up with the bracket at the far end). Put it in a `<bdi>` where it is rendered, in React and in popup HTML (`news-safety.ts`). Where the element clamps or truncates it (`truncate`, `line-clamp-*`), give that element `dir="auto"` instead: the text then runs in its own direction, so the cut and the "…" land at its end rather than eating its first letters. Such a block aligns with its own text, so a German headline on its own line sits left in an Arabic tile. In a row, keep the `dir="auto"` element only as wide as its text and give the free space to a neighbour (`ms-auto` on the chevron in `TransitStrip`), or the text drifts away from what it belongs to. Logical margins, paddings and `text-start`/`-end` on a `dir="auto"` element follow the text's direction, not the page's, so put them on a wrapper (the district in `PoliticalStrip`); `logical-sides.test.ts` fails otherwise. Neither adds `lang`, so screen readers in DE/EN/TR are unchanged. `NinaBanner` is the exception: it says outright that a warning is the official German text ("Official text in German" outside German, `nina.officialGerman`), so its headline, instruction and description also carry `lang="de"` and a screen reader reads them as German; its one-line headline is the `dir="auto"` case. The strip tests (`NewsStrip`, `PoliticalStrip`, `TransitStrip`, `EventsStrip`), `NewsMarquee.test.tsx`, `NinaBanner.test.tsx` and `news-safety.test.ts` pin it.

The mirroring reaches only logical sides: use `ps-`/`pe-`, `ms-`/`me-`, `text-start`/`text-end`, `inset-s-`/`inset-e-`, `border-s`/`border-e` and `rounded-s`/`rounded-e` rather than `pl-`, `ml-`, `text-left`, `right-0`, `border-r` or `rounded-r-`; in popup HTML, `margin-inline-start`, `padding-inline-start`, `border-inline-start` and `text-align:end`; in a React style, `insetInlineStart`. With `right-0`, the phone menu in `HeaderControls` would stay anchored right in Arabic, where its button sits at the left edge, and open off the screen; `inset-e-0` keeps it on screen (`HeaderControls.test.tsx`). `src/logical-sides.test.ts` reads every class string and inline style in the web source and fails on a physical side, except the few listed there with the reason they stay physical (the centred city name in `TopBar`, the scroll indicator placed over the skyline picture, the region numbers in `CrisisStrip`); it also compiles every logical utility used, so a misspelt one fails.

A logical margin on an inline element in running text follows the element's own direction, not where bidi places it. Inside a left-to-right run in an Arabic page (a German name, a number with a Latin unit) the element is still right to left, so `ms-1.5` lands on the run's outer side and the words touch ("Tegeler See15.5°C", "8.1µg/m³"). Isolate the run first: `dir="auto"` on the element holding it (`BathingStrip`), `<Ltr>` around number and unit (`AirQualityStrip`), `ltr()` in popup HTML (the swatch in `air-quality.ts`). `logical-sides.test.ts` fails on an inline `ms-`/`me-`/`ps-`/`pe-` or `margin-inline-*` beside other inline content that is not isolated, unless it is listed there because the text around it is translated and so runs in the page direction. Movement mirrors too:

- **`MobileLayerDrawer`** (phones' layer rail) is anchored at `inset-s-0` and slides along the inline axis: its offsets are logical and multiplied by the direction for `translateX` and for a finger's movement, so in Arabic it closes off the right edge with its button on screen and opens on a leftward swipe (`MobileLayerDrawer.test.tsx`).
- **`NewsMarquee`** moves towards the inline end. A right-to-left track starts at the right edge and overflows to the left, so `[dir='rtl'] .marquee-track` sets `--marquee-shift: 50%` for the `marquee` keyframes; moving it left like a left-to-right track emptied the bar within seconds. The two copies carry their own trailing space (`pe-8`, no gap on the track), so half the track is exactly one copy and the loop doesn't jump. Reduced motion stops it in both directions.
- **The AQI scale** in `AirQualityStrip` mirrors with its flex segments; its marker is placed with `insetInlineStart` and centred with `-ms-1.5`.
- **CSS that is not ours** stays physical, so `globals.css` flips it under `[dir='rtl']`: MapLibre's popup close button moves to the top-left, where it no longer covers the start of the title, and the drawer button's breathing scale grows from the right edge.

## Language Detection

Priority: `localStorage` (key `language`) → `navigator.language` → fallback to `en`. Only `supportedLngs` (`de`, `en`, `tr`, `ar`) are accepted.

The detector tests once, inside `try`/`catch`, whether storage works and keeps the answer for the page. With site data blocked it skips storage, uses the browser language and doesn't persist a switch (`src/i18n/storage-blocked.test.ts`).

## Usage in Components

```typescript
import { useTranslation } from 'react-i18next';
const { t, i18n } = useTranslation();
t('panel.news.title')  // → "News" or "Nachrichten"
i18n.changeLanguage('de')
```

Outside React (map popups are HTML strings), `import i18n from 'i18next'` and call `i18n.t(...)` when the text is built, not at module load, so it follows a language switch. Escape the result before it goes into markup.

Dates, times and grouped numbers take `i18n.language` as the locale: `n.toLocaleString(i18n.language)`, `d.toLocaleDateString(i18n.language, …)`. Never pass `undefined` or no locale, which formats in the browser's language rather than the one picked in the UI. Name the month (`{ day: 'numeric', month: 'short', year: 'numeric' }`, plus `timeZone: 'UTC'` for a date-only ISO string) rather than showing a numeric date: English "8/5/2026" reads differently outside the US. Arabic gets whatever the browser's `ar` locale gives, as in every tile. Decimals written with `toFixed` (percentages, readings) keep a point in every language. A shortened amount keeps that number and takes its scale word from `number.scale.*` ("38.5 bn", "38.5 Mrd.", "38.5 Mr", "38.5 مليار"). `lib/format-value.ts` holds both rules (`formatCount` and `formatDecimal`) for the tiles that use it (frontend.md → Frontend Utilities). The strip tests (`WastewaterStrip`, `BathingStrip`, `PopulationStrip`, `LaborMarketStrip`, `FeuerwehrStrip`, `BudgetStrip`, `WaterLevelStrip`) and `popup-language.test.ts` pin this.

## Language Switcher

`HeaderControls` (rendered by `TopBar` and `PageShell`) builds one button per code in the current city's `languages` (`packages/web/src/config/cities/*.ts`: Berlin DE/EN/TR/AR, Hamburg DE/EN; `['de', 'en']` when no city is selected). Inline on desktop, inside the hamburger menu on mobile. The active language is highlighted and has `aria-pressed="true"`, so screen readers announce it too. Stored in localStorage by i18next.

## Testing

`test-setup.ts` initializes i18n with English active, so test assertions match English strings. All four bundles are registered, so a test can `i18n.changeLanguage('ar')` (and switch back in `afterEach`).

## AI disclosure copy

The `aiLabel.*`, `aiNotice.*` and `sources.aiProcessing.*` strings are the EU AI Act labels, approved word for word by the owner, except the DE, TR and AR `aiLabel.tooltip`, which were derived from approved copy and await confirmation (`ai-transparency.md` §7). Don't reword them in passing: a change needs the owner's approval, and `src/test-fixtures/approved-ai-copy.ts` holds the approved text so the rendering tests fail until it is updated too. Where they are shown and why: `.context/ai-transparency.md` §7.

## Adding a Language

1. Create `packages/web/src/i18n/{code}.json` with all keys
2. Import it, add it to `resources` and add the code to `supportedLngs` in `packages/web/src/i18n/index.ts`
3. Add the code to `languages` in each city's web config (`packages/web/src/config/cities/*.ts`) where it should be offered; the switcher reads that list
4. Add it to the server city config's `languages` (`packages/server/src/config/cities/*.ts`) so the daily briefing is generated in it too
